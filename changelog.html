Changelog

What shipped, and when

CutLab is in beta and changes in the open. This page records the releases as they landed, newest first. The MCP tool reference lives in the MCP documentation.

9 November 2026

The Agent Control release

The MCP stops being a render-only relay and becomes the full control surface for the editor. Until this release an agent could list projects and render queued jobs, seven tools in total, and could not change a single edit. Now the whole engine is agent-callable:

  • 100% of the engine. Every edit CutLab can make — clip, grade, effects, captions, export — is callable through MCP. Zero UI-only features: if the interface can do it, your agent can too.
  • Full MCP vocabulary. Ten tool groups, A–J: project operations and batch edits, media upload and registry, timeline and clip operations, transform and keyframes, effects and transitions, the full grade object with LUTs and qualifier key, text and captions, audio including voice separation, analysis and AI jobs, and the complete export surface. Every write is schema-validated, revision-checked against stale copies, and recorded in the project's edit log.
  • Live-channel parity. The control channel that drives the open editor speaks the same vocabulary as the MCP, with live preview feedback while you watch: the same operation names work on a cloud project or on the app in front of you.
  • Delivery and interchange. Caption export (SRT and VTT) straight from transcription word timings, still and cover export as a first-class job, a GIF export preset, loudness target presets on the audio bus, and EDL/XML export of the timeline.
  • Render verification. Every finished render returns its probe facts and sampled frame grabs to whoever asked for it, agent or UI. Failed renders return structured, stage-level errors, and a failed render gets one automatic retry with its inputs warmed.
  • Seeing the grade. A new grab_still tool renders a single frame to a signed URL, so an agent can look at its own colour work before queueing a full render.

6 November 2026

Editor redesign and the public surface

  • UI redesign. The editor was rebuilt surface by surface: foundations and fonts, viewer, accent and focus system, page skeleton, top bar and timeline, media page, inspector and prompt panel, colour page, audio page, deliver page and the narrow layout, closing with a local mirror of the finished design.
  • Landing rebuild. A new start page for the public site, with the demo film of the editor as it ships.
  • Auth redesign. A split-layout sign-in, and the forgot-password flow the old modal never had.
  • Home port. The workspace Home (prompt bar, quick ways in, recent sequences, cloud projects) became the editor's front door.
  • Theme unification. Help and legal pages brought onto the same public theme as the landing.

5 November 2026

Phase 3: the public surface

  • Account dashboard. Your projects and versions, a storage meter against the real 200 MB quota, job history with lane markers, connect token labels, change password, and Export my data: everything the relay holds for you, as a download.
  • Delete account. A self-serve function that sweeps your storage, removes your rows across the relay tables and deletes the login, in an order that leaves the account retryable if a step fails.
  • Landing and help. The public site: landing page, a help index and four help pages (connect your AI, render with your Muse, files and quotas, export and delete), written under the house anti-slop rules with real screenshots of the shipped app.
  • Legal pages. Terms, privacy and content policy, drafted for the data flows as they actually work: the shared login, relay storage, renders on your own machine, prompt-lane flows, token hashes only.
  • Support and operations. In-app feedback, a relay health check, and table backups with an integrity check and a restore drill artifact.
  • Deployed and accepted the same day, including the feedback migration going live.

5 November 2026

Phase 2: Bring Your Own Muse

  • The MCP connector. The first MCP release: seven tools that let your own assistant find renders queued for it, claim one under a one-hour lease, fetch the project and media, render it locally and upload the result. Authentication is the clt_ connect token; only its hash is stored, and every query is scoped to its account.
  • Lane split. Render jobs carry an execution lane, server or agent. The server worker provably never claims agent-lane jobs.
  • Portable renderer package. The renderer ships as a standalone package (version 1.0.0, then 1.0.1), byte-identical to the server's own renderer, with an agent brief covering the whole claim-to-complete protocol. Hosted publicly so an agent can fetch it itself.
  • Client. The export panel gained the Render with choice: CutLab server or your own Muse.

4 November 2026

Phase 1: lockdown and accounts, on a working editor

  • Accounts. Email sign-in and sign-up, plus Google and GitHub OAuth. Sessions persist and refresh; an auth failure never blocks local editing.
  • Owner-only relay. Every relay table and file scoped to its account and enforced by the database itself, with the quotas that still stand today: 50 MB per file, 200 MB per user. Signed-out local editing is untouched by design.
  • Jarvis control, owner-gated. Remote control of cloud projects, gated to the owner account in three places, with connect tokens registered to an account.
  • Live control. A command channel through the relay that drives the open editor: open a project, add and trim clips, set volume, add text, save, queue jobs and renders, take preview snapshots.
  • The editor underneath. By this point the editor and its server renderer were already verified end to end: five clip types, keyframed animation, masks and chroma key, a Premiere-class grade object with wheels, curves, HSL and LUTs, multicam with audio-synced angle cutting, voice isolation, smart reframe, transcription with word timings, object tracking, beat detection, prompt editing and replicate-an-edit, all honouring one project document that preview and render share.
